# Report format

Respond in the user's language. Be objective; avoid ASO jargon without a short explanation. Do not pad.

## Audit report
1. **Resumo** (3–5 lines: what the app is, main finding, biggest opportunity).
2. **Fontes e limitações** (what was read, what is não disponível).
3. **Score** (per dimension + overall, caps, disclaimer; see `scoring.md`).
4. **Problemas críticos** (with evidence labels).
5. **Oportunidades**.
6. **Recomendações priorizadas**: table `Ação | Impacto | Esforço | Confiança da evidência`.
7. **Metadados propostos** (see below) — or pointer to run `/playgrowth:optimize`.
8. **Plano de crescimento orgânico** (next 30 days, short, concrete, with how to measure in Play Console).
9. **Próximos passos** (user reviews and approves; nothing is published automatically).

## Listing comparison (per field: title, short, long)
- Versão atual (verbatim) and its count `N/limit`.
- Problemas encontrados.
- Nova versão recomendada (+ alternativas) and count `N/limit`.
- Palavras-chave trabalhadas.
- Justificativa.
Long description: print the full text in a code block for easy copy.

## Rules
- Facts vs hypotheses must be distinguishable (evidence labels).
- No promises of ranking positions or install numbers.
- If access to the page failed, say so first.
